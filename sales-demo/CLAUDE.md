# sales-demo — guidance for coding agents

Stack: Python 3.12, `openpyxl` for Excel I/O, `pytest`. Standard library
otherwise (no pandas). Run everything from this directory.

- Package name `sales_processor`; entry point `python -m sales_processor`.
- All money is `decimal.Decimal`, parsed from strings. Never `float`.
  Write money to Excel as Decimal-exact values or strings, never a rounded float.
- Never modify the input workbook; open it read-only.
- Never silently drop a row: every input row ends up accepted, logged as an
  identical duplicate, or quarantined with its original Excel row number
  and a reason from a closed enum.
- Output must be deterministic for identical input (stable sort, no
  timestamps inside data files; duration lives only in the JSON report).
- Inputs: `data/sales_2026_09.xlsx`, `data/sales_2026_10.xlsx`,
  `data/product_mapping.csv`. They are generated by `make_fixtures.py`;
  edit the script and regenerate rather than editing the binaries.
- Tests go in `tests/`. Keep each change small and add tests with it.
- Do not add dependencies beyond `requirements.txt` unless the issue says so.
